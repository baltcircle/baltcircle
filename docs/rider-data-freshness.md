# Актуальность данных пользовательского интерфейса

Исправления аудита R1–R9 от 20 сентября 2026 года. Сервер остаётся источником истины; события ускоряют обновление, HTTP независимо восстанавливает снимки.

## Покрытие

| Проблема | Исправление |
| --- | --- |
| R1: поток поездки переживал смену авторизации | Один поток на текущего пользователя; гостевой клиент его не открывает. Смена аккаунта отменяет запросы, очищает кеш и локальные приватные состояния. |
| R2: пропущенные сообщения и устаревший режим чата | HTTP-сверка при открытии/переподключении SSE, событиях, фокусе, восстановлении связи и периодически. Метаданные разговора приходят вместе с последними сообщениями. |
| R3: только первые 200 сообщений | Последние 50 сообщений плюс курсорная загрузка предшествующих страниц; дедупликация по ID и хронологический порядок. |
| R4: завершение замком не обновляло историю/счётчики | Изменение жизненного цикла поездки из SSE, HTTP или локальной записи обновляет зависимые запросы. GPS-точки не запускают повторную загрузку истории. |
| R5: парковки, зоны и телеметрия | Публичные события каталога и ограниченные по частоте события телеметрии; общий поток карты и резервный HTTP. События не содержат персональных данных. |
| R6: бронь со второго устройства | Обновление по событию флота, повторному входу на экран, фокусу и резервному опросу. |
| R7: устаревшие способы оплаты | Повторная загрузка при открытии; актуализация перед стартом/продлением. Ошибка чтения не означает отсутствие карты и не включает другой способ оплаты автоматически. |
| R8: история 40 и статистика 100 | Авторизованные `/api/rider/history` и `/api/rider/stats`: страницы по 40 и SQL-агрегация всей собственной истории без тестовых поездок. |
| R9: ошибка выглядела как пустые данные | Видимое уведомление, ручной повтор и сохранение последнего успешного снимка; первоначальная ошибка авторизации не трактуется как гостевой вход. |

История сохраняет прежнюю семантику: учитывает собственные нетестовые поездки, включая текущие. Порядок `startedAt DESC, id DESC`; составной курсор исключает пропуски при одинаковом времени старта. `userId` в параметрах запроса не определяет владельца: он берётся исключительно из проверенной сессии.

## Интервалы и восстановление

- Активные поездки и брони: HTTP каждые 10 секунд.
- Открытый чат: HTTP каждые 15 секунд.
- Карта, парковки, зоны, история, статистика, карты/счета: HTTP каждые 30 секунд для подключённых запросов.
- Текущий пользователь: каждые 30 секунд; конфигурация платежей: каждые 60 секунд.
- Фоновые вкладки не опрашиваются стандартным таймером TanStack Query. Возврат фокуса и связи запускает актуализацию.
- SSE heartbeat: 25 секунд; клиентский watchdog: порог 45 секунд, проверка каждые 10 секунд. Публичная телеметрия объединяется в уведомление раз в 5 секунд.
- Активный поток повторяет чтение на heartbeat: живое соединение не считается доказательством успешной загрузки данных.
- Приватные SSE перепроверяют серверную сессию и пользователя перед выдачей данных и на heartbeat; недействительные сессии закрываются.
- Событие соседней вкладки блокирует приватный UI до проверки нового аккаунта. Ответы старого поколения сессии отклоняются; ожидавшая CSRF мутация не отправляется от имени нового аккаунта.
- Ссылки вложений переподписываются при обновлении чата. Ошибка картинки запускает ограниченное по частоте обновление и предоставляет ручной повтор.

Автоматического повтора платёжных мутаций нет. Указанные интервалы являются периодами попыток обновления, а не гарантией времени доставки при недоступной сети или сервере. Тарифы остаются общей конфигурацией сборки клиента и сервера.

## Проверки

- `npm run check`, `npm test`, `npm run build`.
- Регрессионные тесты QueryClient и SSE: вход, смена аккаунта, поздние ответы, CSRF-гонка, зависимые кеши, разрыв потока, heartbeat, HTTP-ошибка, повторное открытие и фокус.
- HTTP-тесты новых маршрутов: анонимный доступ, чужой `userId`, валидация курсора.
- Проверки отзыва сессий SSE при выходе, блокировке, удалении и ошибке хранилища.
- `script/check-admin-data.ts` на отдельной локальной PostgreSQL: все 600 нетестовых поездок, итоговая дистанция, пагинация, 357 сообщений, уникальность, изоляция владельцев. Включено в штатный CI.
- Дополнительная локальная проверка собранного приложения в Chromium с тестовыми API: гостевой вход без reload, 90 строк истории, 357 сообщений и новое SSE-сообщение, ошибка с сохранёнными данными, переключение аккаунта с очисткой черновика, восстановление после первоначального отказа API авторизации.

Реальные списания, поездки, команды замкам и чужие переписки в production не создавались. Работа на физических мобильных устройствах и реальные операторские сети не подменяются этими изолированными проверками.
